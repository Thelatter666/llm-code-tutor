## 4. 实现中踩过的坑（接手方必读）

1. **新构造 ORM 行的列值是 None**：SQLAlchemy 的 `default=` 在 flush 时才应用。`MistakeBookService.record_result` 对新条目必须先归一化（`or 0` / `bool()`）再喂状态机，否则 `NoneType += int` 崩溃。Task 13 种子直插 Exercise 时同理注意。
2. **15s 预算测试是真实时序**：`test_coding_budget_abort_*` 用 `delay_s=0.2` + `budget_seconds=0.35` + 5 用例，断言写的是不变量（`skipped>=3`、`passed+skipped==5`、分数=通过比例），不要改成精确计数。`time.sleep` 只会过睡不会少睡，但高负载会加大过睡幅度。
3. **H-1 负载敏感**：`test_code_executor.py::test_memory_hog_is_killed_by_memory_layer` 与契约测试都真起子进程；**禁止满负载并行跑测试**（别同时跑 vite build）。
4. **ruff 纪律**：新文件必须零告警。常见三坑：C408（禁止 `dict()` 调用，写字面量）、UP017（测试里用 `from datetime import UTC`，先例 `test_code_run_models.py`；app 代码沿用 `timezone.utc` 是既有约定，别学）、I001 import 排序。用 `ruff check --fix` 后**文件会被改，必须重新 Read 才能再 Edit**。
5. **Mock 模式判定在配置层**：要测「真提供方」路径，测试必须先 `get_or_create_singleton(session)` 后设 `cfg.provider="openai_compat"`、`cfg.api_key_encrypted=encrypt_api_key("sk-test")`（P3 同款），否则走 Mock 启发式——`test_short_*` 有现成样例 `_make_real_provider_config`。
6. **lint 基线 35 errors 是存量归属**（M-1，P6 后清理批次）：只保证新文件零告警、总数不涨，禁止顺手修存量。
7. **判分豁免不走 PromptAssembler**：简答评分的 system/user 消息由 `domain/exercise/short_scoring.py` 构建，服务层包 `ChatMessage`。hint 则相反——**hint 必须走 PromptAssembler**（模板已在 `TEMPLATES` 注册），不要混淆这两个决定。
