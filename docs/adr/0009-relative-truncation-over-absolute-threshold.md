# 相对截断与绝对阈值并存

检索命中同时受两条规则约束：绝对阈值（`score_threshold`，按 embedding 模型分别取
0.25 / 0.35 / 0.30）与相对截断（与最佳命中分差 > 0.15 一律丢弃）。二者叠加，不是二选一。

## Considered Options

- **只用绝对阈值**：实现简单、语义直观（「相关度不低于 X 才算命中」）。但余弦相似度的
  **绝对值分布随 embedding 模型而异** —— OpenAI 的 embedding 分布整体偏高，MiniLM 的偏
  低。同一个 0.35 在 A 模型下几乎全命中，在 B 模型下几乎全丢弃。切换 embedding 模型
  （spec §8.7 明确支持的运维动作）后，检索行为会在管理员毫无察觉的情况下整体漂移。
- **只用相对截断**：跨模型可比，切换模型后行为稳定。但没有任何绝对下界：当知识库里
  **根本没有相关内容**时，最佳命中本身可能只有 0.1，相对截断会把这一堆噪声全部留下，
  于是「知识库无相关内容」永远不会被识别出来 —— 模型会基于无关片段理直气壮地作答。
- **两者叠加**：绝对阈值负责「有没有相关内容」这个绝对判断，相对截断负责「哪些命中
  值得进 prompt」这个相对排序。前者绑定模型（故按模型给默认值），后者跨模型可比。

## Consequences

- 顺序固定为：先绝对阈值 → 再相对截断 → 最后多样性截取。反过来会让「一堆低分命中中
  分数最高的那个」因为相对截断而存活。
- 相对截断的 0.15 是固定值，不开放后台配置 —— 它是跨模型可比的那一条，开放配置等于
  把这个性质又破坏掉。
- 两条规则都定义在 `domain/knowledge/retrieval.py` 的纯函数里，可脱离数据库单测。
- 已知代价：当查询与整个知识库都只是弱相关时，绝对阈值会先把最佳命中滤掉，此时结果
  是「零命中降级」而非「返回弱相关片段」—— 这是刻意的，spec §7.2 步骤 7 的选择。
